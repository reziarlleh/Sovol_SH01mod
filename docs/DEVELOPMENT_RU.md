Текущие исходники — 1.5.1, штатная G24_V2.1 / HC32F005C6PA. Патч управления
собран и проверен на ПК, пока не прошит; [описание](PATCH_1_5_1_RU.md).
Подтверждённая стабильная база — 1.5.0 от 26.10.2026.
Для записи готового образа используйте [FLASHING_RU.md](FLASHING_RU.md),
для версий/пакетов — [TOOLS_RU.md](TOOLS_RU.md).

## Сборка из исходников

Windows PowerShell 5.1/7, Python 3.10+, Arm GNU GCC 15.3.1. Проект не требует
заводского BIN: исходники приложения и необходимые DDL/CMSIS включены в Git.

```powershell
.\tools\fetch_tools.ps1
.\tools\build.ps1
.\tools\prepare_host_tests.ps1
.\tools\test.ps1
python -m unittest discover -s tests -p test_readback_tools.py
python .\tools\audit.py
```

Версия в `src/config.h`. Результаты — `build/v1.5.1/`. Сборка не обращается к COM.
Компиляторы устанавливаются локально в `toolchain/` и `.tools/`, PATH не меняется.
Архивы и подготовленные инструменты можно проверить без загрузки/установки:

```powershell
.\tools\fetch_tools.ps1 -IncludeProgrammer -VerifyOnly
.\tools\prepare_host_tests.ps1 -VerifyOnly
```

## Проверки

Девять C-наборов компилируют настоящий код: actuators, controller, sensor,
dual_sensor, sensor_timing, bus, lcd, storage, resume. Покрыты все профили, отдельные черновики CUSt,
отмена и сбой питания на каждой странице, 1–5 и 96 часов, просмотр цели 5 с,
антидребезг/M/POWER 1,5 с, мигание/просмотр ошибок, все заполнения вентилятора,
двухтональный сигнал, прерывания записи/стирания Flash, совместимость старых
записей и восстановление контроллера из журнала. sensor_timing моделирует обмен
1–25 мс, ожидание после ACK, NACK готовности и CRC с потреблённым ответом.

Python-набор проверяет offline-утилиту: полный HEX/BIN, обрезанные файлы,
пропуски/дубли HEX, контрольные суммы, неверное приложение, padding, CRC журнала,
неизменяемую область и сравнение двух оригинальных копий.

ARM-аудит проверяет формат/совпадение HEX/BIN/ELF, векторы, сильный SysTick,
Flash/RAM, версию, имена/параметры профилей и оба порядка кодов длительности. Это статический аудит; приёмка устройства фиксируется
отдельно в STATUS_RU.md. CI повторяет сборку/тесты/аудит и требует закреплённые
SHA-256 HEX/BIN. При публикации инструкции/утилиты обновляются без изменения
подтверждённого бинарника.

## Flash и локальные данные

Приложение только ниже 0x7000. Журнал — последние 4 KiB, восемь секторов по 512
байт, 25 записей на сектор. Linker, HEX-проверка и аудит контролируют границу.
Page erase сохраняет журнал, chip erase удаляет. [Формат](PERSISTENCE_RU.md).

Распаковки инструментов, build, .repowise и hardware-local исключены из Git.
Физические дампы, заводские backup и сессионные логи не включать в релиз.
Дистрибутив готового релиза содержит Git-исходники, подтверждённые артефакты и
закреплённый архив XHSC. Большие компиляторы загружаются отдельно по SHA-256.

## Публикация

После приёмки владельцем, чистого commit и успешного CI издатель запускает
`python tools/package_release.py --owner-confirmed-on YYYY-MM-DD --ci-url URL`.
Комплект создаётся в `build/release/v<версия>/`: исходники, Windows ZIP с готовым
образом и архивом XHSC, отдельные артефакты/инструкции, manifest и SHA256SUMS.
Проверяются закреплённые хеши firmware, исходники аудита и состав папки релиза.
Дампы и неотслеживаемые файлы не добавляются. Проверку SHA/состава нужно повторить
после загрузки вложений на GitHub. Приёмка 1.5.0 зафиксирована в
[BASELINE_1_5_0_RU.md](BASELINE_1_5_0_RU.md); комплект соответствует тегу v1.5.0.
При патче 1.5.x требуется отдельная проверка изменённого кода и приёмка владельцем.
Образы принятой версии не заменяются молча.
